## 4.0 Findings

### 4.1 Medium

**F4-01 State files that are not regular files survive the clear.**
- Evidence: `clear_state` removes a name only when `os.path.exists` is true, with `os.remove` (`orchestrator.py:821-825`); `reset_state` does the same (`:632-633`). `os.path.exists` follows symlinks; `os.remove` fails on a directory. `engine_status` reports `shipped` when `(state_dir / ".complete").exists()`, which also follows symlinks (`server.py:259`).
- E-1l (symlink): a gate writes `review-feedback.txt` and creates `.complete` → `review-feedback.txt`. The clear removes `review-feedback.txt` first, so `.complete` is dangling when tested and is kept. The reviewer returns REVISE with a body; the engine writes `review-feedback.txt`; the link resolves. Result: rc 1 at max iterations, no `BLOCKED.md`, `engine_status` `shipped: true, blocked: false`. The link survives `reset_state` and reappears as `shipped: true` in the next run, without any gate.
- E-1k (directory): a gate runs `mkdir ai/state/.complete`. `clear_state` raises `IsADirectoryError` (Linux; on macOS `unlink` on a directory fails with `EPERM`, so `PermissionError`, inference). The run ends with an exception after `engine end rc=1`; `engine_status` `shipped: true, blocked: false`. `reset_state` and the next run's loop-start clear raise the same error.
- Consequence: the status channel reports SHIP for a run that did not ship, and, unlike F3-01, `blocked` is false. The worker controls it in the default gate set, because the pytest gate runs worker-written tests. The exit code, `engine end rc=1` and the absence of `SHIPPED` in the log remain correct.
- Origin: `clear_state` predates change-82dbf16a. It is not introduced by iteration 4 and was not raised by the earlier audits. It is outside DI-06: the gate has exited and no process is left running.
- Recommendation: remove with `os.path.lexists` and `os.unlink` for files and symlinks, and `shutil.rmtree` for directories (or end the run BLOCKED when a name cannot be removed), in `clear_state` and `reset_state`; report `shipped` only for a regular file that is not a symlink. Add tests for a symlinked and a directory `.complete`.

### 4.2 Low

**F4-02 A tracked task without bytes skips the hash check.**
- Evidence: `_task_bytes` stays `None` when `os.path.isfile(args.task)` is false at `:2385`. `is_tracked_task` (`:2388`) and the pre-run check test the path again. `prerun_missing` compares the hash only when `task_bytes is not None` (`stages.py:400`). With no bytes, the task text is the path string (`:2526`) and the write scope is the project root (`:2535`).
- E-3e: the approved prompt was moved away before the read and restored before `is_tracked_task`. Result: pre-run check `[]`, the run started with the path string as task and `write_scope None`. A dangling symlink at the read is refused earlier (`:2346`, rc 1).
- Consequence: a tracked run proceeds without content binding and with project-root write scope; the worker may read the file later through its tools. The window lies between two `isfile` calls microseconds apart, and the path must also exist at `:2346`. An atomic save (write and rename) does not open it.
- Recommendation: refuse a tracked `loop` or `worker` run with exit 3 when `_task_bytes` is `None`, or make `prerun_missing` require bytes whenever `task_path` is given. Add a test.

## 6.0 Observations

No finding is raised for the following.

1. **Encoding.** The former text-mode read used the locale encoding; the new read uses UTF-8. On macOS the default locale encoding is UTF-8, so no change is expected there (inference; verify with `python3 -c "import locale; print(locale.getpreferredencoding())"`).
2. **Invalid UTF-8.** An approved prompt that is not UTF-8 raises after `mcp.connect()`, outside the `try`/`finally` that logs `engine end`. The former read raised at the same point. Unchanged behaviour.
3. **Normalised text.** The worker receives LF line endings and `{STATE_DIR}`/`{PROJECT_ROOT}` substitution; the hash covers the raw bytes. A lone CR displays as an overwrite in some terminals; this concerns the approval review, not the engine.
4. **Test coverage.** The new tests cover a gate timeout, an unrunnable second gate, and an edit or re-point after the check. They do not cover a change between read and check (verified by E-3c, E-3d), non-regular state files (F4-01) or a task absent at the read (F4-02).
5. **DI-06.** Unchanged; accepted limit.
