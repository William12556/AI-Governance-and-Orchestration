## 1.0 Summary

- **Subject:** `bin/propagate.sh` at `cdd75fe` (blob `65447e19`, mode 100755), change-c5270084 iteration 3.
- **Original findings:** 10 resolved, 1 partially resolved (F-12), 0 not resolved. F-07 is resolved; two new failure paths of the same class are recorded as N-04 and N-05.
- **No-delete claim:** The claim holds in a narrow sense. The script does not delete any file that the source lacks, and every such file was relocated intact in every case tested. The rsync copy still replaces the content of any target file at a path the source also has. Local edits, and files created at such paths while the prompt is open, are lost without a copy or a warning (N-01). On a case-insensitive file system, the same mechanism probably reaches project files whose names differ from a framework file only by case (N-02; this is an inference and has not been tested).
- **New findings:** 0 critical, 0 high, 3 medium, 5 low.
- **Recommendation:** The P02.8.1 criteria for the original audit are met: the critical finding is resolved and both high findings are resolved. Close the audit with human approval. Raise N-01 to N-03 as new P03 issues. Run §8.0 on macOS before the next downstream propagation.

## 2.0 Independence and Method

- The change document was read as a claim. None of the implementer's tests or test results were reused. All cases in §6.0 were built for this audit.
- **Linux VM** (operator's machine; aarch64, GNU bash 5.1.16, rsync 3.2.7, coreutils 8.32): a `git clone --no-local` of the repository at `cdd75fe` was used as the framework. The targets were throwaway directories made with `git archive` of `pre-eb782f83` (9.16) or `HEAD` (10.4), each `git init`-ed.
- **Oracle:** each target was snapshotted before and after a run, recording a git blob hash for every file and the link text for every symlink. Content counts as lost when a pre-run blob that is not a framework object appears nowhere in the target (neither `ai/` nor `ai-local/`) after the run.
- **Cloud container** (x86_64): Apple's `bash-3.2` source (apple-oss-distributions/bash) was built on Linux with two compatibility shims (`xlocale.h`, and a pass-through `fmtcheck`). GNU rsync 3.2.7 was built from source. A subset of the cases was re-run under this bash (X12). This covers bash 3.2 language semantics. It does not cover macOS BSD userland, openrsync or APFS.
- **Static review** of Apple openrsync (apple-oss-distributions/rsync, tag rsync-184): the itemize prefix and the replacement of a directory by a file without `--force`.
- **Repository side effect, disclosed:** one read-only `git status` in the repository left an empty `.git/index.lock` (the same effect recorded in the original audit). The operator granted delete permission and that file alone was removed. After that, no git command was run in the repository. This report is the only file added.

## 5.0 No-Delete Claim

1. **Files absent from the source:** The claim holds. The enumeration is independent of rsync, and each candidate is moved with `mv -n`. After each move the script re-checks that the source path is gone, and any failure exits 3 before the copy. No case lost such a file.
2. **Files present in the source (same type):** The claim does not protect them. rsync without `--delete` still replaces their content (N-01). This is the one remaining route by which project content is lost, and it includes the prompt-window race (X3).
3. **Name equivalence:** `same_type` asks the file system whether the source has the path. On case-insensitive APFS the answer can be yes for a different name (N-02, inferred).
4. **rsync replacements:** Non-regular entries at framework paths (FIFOs) are unlinked (X4). A non-empty directory where the source has a file is refused by GNU rsync (exit 23, X5). The same holds by static reading of Apple openrsync, where `unlinkat(AT_REMOVEDIR)` is attempted without `--force` and fails on a non-empty directory.
5. **The script's own removals:** `rmdir` of empty directories only, and the `mktemp` work directory.

## 8.0 Operator Procedure for macOS

Run in Terminal on the Mac. Everything happens under `/tmp`; the repository is only cloned from.

```bash
export PATH=/usr/bin:/bin:/usr/sbin:/sbin
sw_vers; /bin/bash --version | head -1; which rsync; rsync --version 2>&1 | head -2
F=/tmp/fu-fw; rm -rf $F && git clone -q ~/Documents/GitHub/LLM-Governance-and-Orchestration $F
mk() { rm -rf "$2"; mkdir -p "$2"; git -C $F archive "$1" ai | tar -x -C "$2"; git -C "$2" init -q; git -C "$2" add -A; git -C "$2" -c user.name=t -c user.email=t@t commit -qm base; }

# 1. Itemize prefix (N-03)
rm -rf /tmp/fu-s /tmp/fu-d && mkdir -p /tmp/fu-s /tmp/fu-d && echo a > /tmp/fu-s/f && echo b > /tmp/fu-d/f
rsync --dry-run -a --itemize-changes /tmp/fu-s/ /tmp/fu-d/; echo "rc=$?"

# 2. Up-to-date gate (N-03)
mk HEAD /tmp/fu-t2; echo stale > /tmp/fu-t2/ai/workflow.md
(cd $F && /bin/bash bin/propagate.sh --yes /tmp/fu-t2); echo "rc=$?"; head -1 /tmp/fu-t2/ai/workflow.md

# 3. Case-insensitive name (N-02)
mk HEAD /tmp/fu-t3; rm /tmp/fu-t3/ai/primer.md; echo "PROJECT TEXT" > /tmp/fu-t3/ai/Primer.md
(cd $F && /bin/bash bin/propagate.sh --yes /tmp/fu-t3); echo "rc=$?"; ls /tmp/fu-t3/ai | grep -i primer; head -1 /tmp/fu-t3/ai/[Pp]rimer.md; ls /tmp/fu-t3/ai-local 2>&1

# 4. Full run, BSD userland (C8 remainder)
mk pre-eb782f83 /tmp/fu-t4; echo notes > /tmp/fu-t4/ai/notes.md; echo lead > "/tmp/fu-t4/ai/ primer.md"
(cd $F && /bin/bash bin/propagate.sh --yes --allow-major /tmp/fu-t4); echo "rc=$?"; cat /tmp/fu-t4/ai-local/RELOCATED.md
```

- **Step 1 expected:** a line beginning `>f` (for example `>f.st......` or `>f.st....`) and `rc=0`. Any other prefix confirms N-03 on this Mac.
- **Step 2 expected:** a preview listing `workflow.md`, `rc=0`, and the first line of `workflow.md` is no longer `stale`. "Target is up to date" confirms N-03.
- **Step 3 (inference: the project text is lost):** `Primer.md` is absent from `ai-local/`, and the file's first line is framework text. If `Primer.md` appears in `ai-local/` with `PROJECT TEXT`, N-02 is refuted.
- **Step 4 expected:** 7 `retired framework file` rows (`templates/T0…`) and 2 `project content` rows (`notes.md`, ` primer.md`), `rc=0`.
- Send the four outputs to the auditing session for adjudication.
