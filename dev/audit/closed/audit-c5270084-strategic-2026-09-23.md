## 1.0 Summary

- **Subject:** `bin/propagate.sh` at `d000890` (change-07087e91 plus change-c5270084 iteration 2). Baseline `6f6988b`.
- **Verdicts:** C1 refuted, C2 refuted, C3 confirmed, C4 refuted, C5 refuted, C6 refuted (conditional), C7 confirmed, C8 unverifiable, C9 refuted.
- **Findings:** 1 critical, 2 high, 4 medium, 5 low.
- **Central defect (F-01):** the apply step runs `rsync --delete`, whose deletion set is recomputed at apply time and is not bounded by the classification. Classification only moves files out of the way. Any file the classifier misses, misreads, or never sees is deleted without a record. Four independent routes to unrecorded deletion of project content were demonstrated, one of which reproduces the original solax-modbus loss of `project_information.md`.
- **Consequence for C8:** the safety mechanism depends on the exact text of rsync `--itemize-changes` deletion lines. That text has not been observed on macOS `/usr/bin/rsync`. If it differs, the script behaves as change-07087e91 did.
- **Recommendation:** keep downstream propagation blocked. Remediate F-01 before any live run, then exercise C8 on macOS (§8.0).

## 2.0 Independence and Method

- The brief (v1.1) was read as a witness statement. No implementer test command or test result was reused. All cases in §5.0 were constructed for this audit.
- Environment: Cowork Linux VM on the operator's machine (aarch64, GNU bash 5.1.16, rsync 3.2.7). This is the same class of environment the implementer used; the results therefore say nothing about macOS (C8).
- Framework: a local clone of the repository at `d000890` under the VM scratch area. Targets: throwaway directories built with `git archive` from `pre-eb782f83` (governance 9.16) or `HEAD` (10.3), each `git init`-ed.
- `bin/propagate.sh` was run only against those throwaway targets, invoked as `bash bin/propagate.sh` (see F-11).
- Interactive runs were driven through a pseudo-terminal (Python `pty`) so the confirmation prompt could be held open.
- Two rsync behaviours were simulated with a `PATH` shim. These test the script's dependence on rsync output; they are not claims about macOS rsync.
- Repository side effect, disclosed: an early read-only `git status` against the repository refreshed `.git/index` (stat cache only) and a second one left an empty `.git/index.lock` because the session could not unlink it. With the operator's permission grant, that lock file was removed. `git status` afterwards reported a clean tree. No tracked file was modified. This report is the only file added.

## 6.0 Brief Weak Points Assessed

1. **macOS rsync.** Open. E7 establishes that the safety property depends on the deletion-line text; macOS output is unobserved (C8).
2. **Directory deletions.** rsync 3.2.7 lists every file inside a deleted directory, dotfiles and nested levels included (E1, E2); the `find` expansion is redundant but harmless there. The real gap is type replacement, which emits no deletion line (E1, E3).
3. **Blob scope.** Confirmed as a defect and wider than stated: unreachable objects make deletions unrecoverable (E9); the empty blob and path independence add false deletions (E12). F-02.
4. **Line endings.** No unsafe direction exists: `--no-filters` hashes raw bytes, so a match requires byte identity (E17).
5. **Quoting.** Leading spaces cause wrong-file classification and deletion (E4); newlines and non-ASCII cause aborts (E5). Leading dashes are safe: paths are always prefixed or passed after `--`.
6. **Partial failure.** Relocation-then-abort leaves consistent files but violates the exit contract (E5, E13). Interrupt between move and log: inferred only.
7. **Race.** Confirmed as data loss (E6).
8. **Version parsing.** Worse than suspected: parsing failure aborts silently and blocks new-project initialization (E16). F-03.
9. **Test circularity.** Addressed by §5.0; none of E3–E13 appear in the change's test list.

## 8.0 Operator Procedure for C8

Run on the Mac in Terminal (zsh or bash). Everything is under `/tmp`; the repository is only cloned from. `PATH` is pinned so that macOS `/usr/bin/rsync` is used, and `/bin/bash` forces bash 3.2.

```bash
export PATH=/usr/bin:/bin:/usr/sbin:/sbin
sw_vers; /bin/bash --version | head -1; /usr/bin/rsync --version 2>&1 | head -3

# 1. Deletion-line format (the property F-01 route (d) depends on)
rm -rf /tmp/c8 && mkdir -p /tmp/c8/s/x /tmp/c8/d/old/sub
echo 1 > /tmp/c8/d/old/a; echo 2 > /tmp/c8/d/old/sub/b; echo 3 > /tmp/c8/d/old/.h
echo 4 > "/tmp/c8/d/ lead"; echo 5 > /tmp/c8/d/x; echo 6 > /tmp/c8/d/.DS_Store
/usr/bin/rsync --dry-run -a --delete --itemize-changes --exclude='.DS_Store' /tmp/c8/s/ /tmp/c8/d/ > /tmp/c8.out 2>&1; echo "rc=$?"; cat -v -e /tmp/c8.out

# 2. Script under bash 3.2 and macOS rsync, throwaway target
rm -rf /tmp/c8fw /tmp/c8p && git clone -q ~/Documents/GitHub/LLM-Governance-and-Orchestration /tmp/c8fw
mkdir -p /tmp/c8p && git -C /tmp/c8fw archive pre-eb782f83 ai | tar -x -C /tmp/c8p
echo project > /tmp/c8p/ai/notes.md; mkdir -p /tmp/c8p/ai/old; echo y > /tmp/c8p/ai/old/a.md
cd /tmp/c8fw && /bin/bash bin/propagate.sh --yes --allow-major /tmp/c8p; echo "rc=$?"
ls -R /tmp/c8p/ai-local; ls /tmp/c8p/ai/templates
```

- **Step 1 expected (rsync 3.x behaviour):** one line per file of the form `*deleting   old/a` (with `$` at line end under `cat -v -e`), `old/sub/` and `old/` listed, and `x` absent. Any other prefix or spacing, or an omitted file, means the classifier misses those files on macOS and C8 is refuted.
- **Step 2 expected:** preview lists seven `delete templates/T0…` lines and two `relocate` lines (`notes.md`, `old/a.md`); ai-local/ holds `notes.md`, `old/a.md` and `RELOCATED.md`; templates hold `T01-requirements.md` … `T08-audit.md`; exit 0. Any divergence refutes C8.
- Send both outputs to the auditing session for adjudication.
