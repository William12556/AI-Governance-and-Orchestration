## 2.0 Independence and Method

- This session is neither the implementing session nor the closure-audit session. The B5 entry in `iteration_3.open_findings` (`fix`, `fix_test_results`, `fix_macos_results`) was treated as a claim. None of the implementer's tests, shims or drivers were reused. The pty driver, target builder and shims were written for this check.
- **Environment:** Cowork Linux VM on the operator's machine (aarch64, GNU bash 5.1.16, GNU findutils 4.8.0, rsync, strace), running as a non-root user.
- **Framework copies:** A `git clone --no-local` of the repository was made in scratch space outside the repository and checked out at `90f3a8d` (the fix). A detached worktree of that clone at `5fa78e7` (blob `df0c517`, iteration 3) was used for side-by-side comparison.
- **Targets:** Throwaway directories built from `git archive HEAD ai`, with populated `workspace/`, `state/` and `logs/` and project `context.md` and `task.md`. For update cases, `ai/primer.md` was replaced by the older blob at `dd58ce0`. The script was never run against a real project.
- **Prompt races:** A Python pty driver waited for `Apply changes?`, ran the mutation, answered, and recorded the exit code. Faults after planning were injected with PATH shims for `date`, `sort`, `find`, `cksum` and `cp`.
- **Write check:** One full interactive apply (update, relocation, backup and seeding, with `logs` symlinked to an external directory) ran under `strace -f` for the file-mutating syscalls and `openat`.
- **Repository access:** Read-only, and every git command used `--no-optional-locks`. After the reads the tree was clean and `.git/index.lock` was absent. This report is the only file added.
- **Not exercised:**
  - macOS, APFS, BSD `find` and bash 3.2. The bash 3.2.57 source and GitHub mirrors were refused by the egress proxy (HTTP 403), so bash 3.2 was checked by static reading. `BASH_COMPAT=32` under bash 5.1 was run as weak supplementary evidence only.
  - Case-insensitive file-system behaviour (§5.2, I-1) was reasoned about statically.
  - The operator's `fix_macos_results` (A) and (B) are taken as operator evidence (§5.3).

## 5.0 New Routes Introduced by the Fix

### 5.1 Content loss and changes applied after a target change

- **None found.**
  - **The script never writes the declared directories (claim confirmed).** Statically: rsync excludes `/workspace`, `/state` and `/logs` without a trailing slash, so symlinks are excluded too; `is_declared` and the `list0` prune keep them out of relocation and backup; the `rmdir` loop prunes them; seeding touches only `context.md` and `task.md`. By experiment (W1): under `strace -f`, no `openat`, `rename*`, `unlink*`, `mkdir*`, `rmdir`, `link*`, `symlink*`, `chmod`, `utimensat`, `truncate` or `fchownat` call named any of these paths, not even a read-only `openat`. The manifest (inode, type, mode, size, mtime, ctime and checksum) of the declared directories and of the external `logs` target was identical before and after.
  - **No post-prompt decision reads declared content.** Plan decisions for a symlink at a framework path are type-based (`same_type`); backups require `-f` and `! -L`. A symlink from a framework path into `state/` is relocated as a link and is not written through (R1: the edit made behind it during the prompt was kept, exit 0). Replacing a framework directory with a symlink into `state/` during the prompt changes the snapshot (R3: exit 3).
  - **A1:** `context.md` and `task.md` stay in the snapshot. A1 and A6 pass (§7.0).
  - **Before the fix,** an edit behind a framework-path symlink into `state/` refused the run. It now proceeds. The outcome is the same as for an up-to-date link, and no content is lost (I-2).

### 5.2 Information items

- **I-1, case-mismatched declared directory (static, APFS):** `-path` matches bytes, so `ai/State/` is not pruned, although `[[ -d ai/state ]]` is true on a case-insensitive file system. Its contents are walked and compared. The mismatch is refused in both modes by the letter-case check in `add_rec` (exit 3). If `State/` holds unreadable content, an interactive run refuses with "cannot snapshot" instead of the more specific letter-case message. The result is fail-closed, and the check covers more rather than less.
- **I-2, symlinked declared directory:** This is recorded by its link text only. A change behind the link, or of the target's type, is not detected. This is harmless because the script neither reads nor writes through it. It is consistent with "contents are not checked" in guide §3.3.
- **I-3, guide wording:** "if a directory cannot be listed" does not mention that an unreadable *file* in `ai-local/` also refuses an interactive run. This belongs to the `ai-local/` residual, which is out of scope and kept by design. It is recorded for completeness only.

### 5.3 Portability

- **Empty `-path` pattern, GNU `find` (tested):** `find . -path "" -print` prints nothing, exits 0 and writes nothing to stderr. `find . \( -path "" -o -path "" -o -path "" \) -prune -o -print` lists every entry, including `.`. The empty pattern therefore matches nothing and does not prune the root.
- **Empty `-path` pattern, BSD `find` (static and operator evidence):** BSD `-path` calls `fnmatch(pattern, path, 0)`, and an empty pattern matches only the empty string, which is never an `fts` path. Operator result (B) is consistent with this and requires it: the snapshots succeeded (no "cannot snapshot"), and a file created in `ai-local/` was detected, so `ai-local/` was walked and not pruned. Operator result (A) shows that `./state` is pruned on macOS (mode 000 `state/x`, up to date, exit 0). Confidence: high. The remaining gap is a direct run of `find /tmp/x -path "" -print` on macOS.
- **bash 3.2 (static):** Every construct in the diff is present in bash 3.2: `local` with several names; assignment and test kept apart; `[[ == ]]` with a quoted right-hand side (a literal comparison); `[[ -L/-d/-e ]]`; `for … in` over words; `if/elif/else` with `|| return 1` on each branch; quoted empty strings passed as arguments, which are preserved; `l="$(readlink -- …)" || return 1`, which keeps the substitution status. The variables are always assigned before use, so `set -u` is satisfied. Every command in the new loop ends in `|| return 1`, so `snapshot()` does not depend on `set -e` inside `$(…)`. Under `BASH_COMPAT=32` (bash 5.1), E1 exited 0 and G01 exited 3. This is weak evidence only.

### 5.4 Documentation

- **guide-install §3.3 (v0.9):** Matches the behaviour. The prompt guard covers `ai/` outside `workspace/`, `state/` and `logs/`, whose contents are not checked, and it covers `ai-local/`. Changes of entry or type at the declared directories still refuse, which is consistent with the wording. See I-3 for one omission that belongs to the out-of-scope residual.
- **`snapshot()` header (lines 263–270):** Matches the behaviour. The declared directories are recorded by entry and type and are never read (confirmed by W1), and the script never writes them (confirmed by W1). The comment on the empty pattern (line 290) matches the GNU test and the macOS evidence.
